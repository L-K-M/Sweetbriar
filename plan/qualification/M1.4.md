# M1.4 owner qualification (O5, O9)

The owner runs these on their Mac with the CI-built app (O3: the
`Sweetbriar-app` artifact of the merged commit) and records the date,
the commit and each result here. CI can't: it has no real mailboxes,
and its numbers are diagnostic (spec/08).

## O5: import Apple Mail exports

Prepare: in Apple Mail, Mailbox → Export Mailbox… for a few mailboxes
of different sizes, at least one with attachments. Note each mailbox's
message count as Apple Mail shows it.

1. File → Import… and choose the exported `.mbox` packages.
2. The sheet lists every package as a source with its message count,
   and any problem with its reason. A source asking for a variant
   offers both choices.
3. Import. Progress advances; Close leaves it running, and File →
   Import… shows the sheet again.
4. The sheet ends "Import finished". Show Report opens the report.
5. For each mailbox, the report's imported plus duplicate counts match
   the count Apple Mail showed, and the sidebar lists it with that many
   messages.
6. In each imported mailbox, scrolling is fluid, ↑ ↓ move the
   selection, and ⇧-click and ⌘A select ranges.
7. Quit during an import, then relaunch: the sheet comes back and the
   job finishes with the same counts.

Result: _date, commit, pass or fail per step, notes_

## O9: store-backed list benchmark

1. Import a mailbox with as many messages as you have (O5); the larger
   the better, 500,000 rows for the full scroll result.
2. Debug → Run Store Benchmark. Keep the window in front until the
   report shows; Copy it here.
3. The report's functional checks pass, and at p95: switching mailbox
   shows first rows within 100 ms, a scroll update costs under 5 ms of
   main-thread work, and selection feedback takes under 50 ms (spec/08
   "Performance budgets").
4. Debug → Run List Benchmark still passes its checks.

Result: _date, commit, the two reports, verdict_
