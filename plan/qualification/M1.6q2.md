# M1.6q2 owner qualification: Search keystroke benchmark

Time Search from the last keystroke to the first rows in the app on
your Mac, over the same seeded synthetic archive M1.6q times in the
core (100,000 messages, no mail of yours), and record the dated result
here against spec/08's budget.

## Seed the archive

On a release build, with the Mac otherwise idle (pick a directory that
doesn't exist yet; the import takes a while):

```sh
SB_SEARCH_TIMINGS_ROOT=~/sweetbriar-search-archive \
SB_SEARCH_TIMINGS_SEED_ONLY=1 \
SB_SEARCH_TIMINGS_OUT=~/sweetbriar-search-archive/seed.json \
  cargo test -p sb-engine --release --lib search_timings -- --ignored --nocapture
```

## Run the benchmark

Launch the Release app over that archive and leave it in front until
it quits (each query is typed ten times):

```sh
open -W -n -a /path/to/Sweetbriar.app --args \
  -runSearchBenchmark ~/search-benchmark.json \
  -dataRoot ~/sweetbriar-search-archive/store \
  -cacheRoot ~/sweetbriar-search-archive/cache
```

Launched with only `-dataRoot` and `-cacheRoot`, Debug → Run Search
Benchmark runs the same queries and shows the report in a window.

The run types each query into the search field, all but its last
character first, then times the last character to the first display
frame showing the new rows. The 30 ms debounce is included. Queries:
an exact reference word, an exact sender address, a phrase, a sender
domain and date scoped to Projects, and a word without a body word.

| Budget (spec/08) | Report field | Result |
|---|---|---|
| Search results after the last keystroke: p95 under 100 ms | `search.budget` (`p95Milliseconds`, `met`) | |

`met` is empty when the run failed a check or a sample never rendered;
see `failures`. Also note `search.perQuery`, the environment block
(Mac model, macOS, refresh rate) and `storeMessages`. A missed budget
is a finding to resolve, not a threshold to relax.

Result: _date, commit, Mac, p95 and budget met or missed, notes_
